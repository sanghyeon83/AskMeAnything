# mac-screen-control — 맥 화면 보기·조작

`mac.js` 하나로 캡처·창·마우스·키보드를 처리한다. 설치할 것 없이 macOS 기본 도구
(osascript·screencapture·sips)만 쓴다.

```bash
osascript -l JavaScript ~/.claude/skills/mac-screen-control/mac.js <동작> [인자]
```

설치: 이 폴더를 `~/.claude/skills/mac-screen-control/` 에 둔다. 원본은 AskMeAnything 저장소 `skills/mac-screen-control/`.

**"computer-use 도구가 없으니 못 한다"고 답하지 마라.** 이 스킬이 그 역할이다.
(2026-09-30 센더2 세션이 그렇게 답해서 이 스킬을 만들었다.)

## 동작 목록

| 동작 | 인자 | 하는 일 |
|---|---|---|
| `info` | — | 화면 배치·배율·커서·앞 앱·권한. **작업 전에 먼저 부른다** |
| `windows` | `[걸러낼말]` | 보이는 창(창id·pid·앱·x,y,w,h·제목). 위에 있는 창부터 |
| `front` | `<앱\|pid> [창제목일부]` | 앞으로 세운다. 최소화면 복원한다 |
| `ui` | `<앱\|pid> [깊이=4] [최대줄=150]` | 앞 창의 버튼·입력칸 등 요소와 **중심 좌표** |
| `capture` | `--region x,y,w,h` / `--window 창id` / `--screen n`, `--max 픽셀`, `--out 경로` | 캡처. 저장 경로와 **좌표 환산식**을 출력한다 |
| `click` | `x y [right\|double]` | 클릭 |
| `move` | `x y` | 커서 이동만 |
| `drag` | `x1 y1 x2 y2` | 끌기 |
| `scroll` | `x y 양` | 휠. 양수=위로, 음수=아래로 (줄 단위) |
| `cursor` | — | 현재 커서 좌표 |
| `type` | `"글자" --to <앱>` | 글자 입력. 한글 안전 |
| `key` | `조합 --to <앱>` | 단축키: `cmd+s`, `cmd+shift+z`, `return`, `esc`, `tab`, `down`, `f5` … |

## 권한

- 클릭·키 입력은 **손쉬운 사용**, 캡처는 **화면 기록** 권한이 필요하다. 권한은 이 스크립트를
  실행한 **앱**에 붙는다. Claude 데스크톱 앱은 둘 다 허용돼 있어서(2026-09-30 확인)
  앱 안의 모든 세션이 그대로 쓸 수 있다.
- 터미널에서 띄운 CLI 세션은 권한이 터미널 앱 기준이라 다를 수 있다. `info` 로 먼저 확인한다.
- `info` 가 꺼져 있다고 하면 **사용자에게 시스템 설정 > 개인정보 보호 및 보안에서 켜 달라고 한다.**
  권한 데이터베이스를 직접 고치거나 다른 방법으로 돌아가지 않는다.

## 좌표계 — 제일 많이 틀리는 부분

모든 좌표는 **포인트**다. 원점은 메인 화면(맥북 내장, 메뉴막대) 왼쪽 위, y 는 아래로 커진다.

| 이 맥 (2026-09-30) | 위치 | 크기(pt) | 배율 |
|---|---|---|---|
| 화면1 맥북 내장 (메인) | 0,0 | 1512 x 982 | 2x |
| 화면2 외장 모니터 | 1030,-1080 | 1920 x 1080 | 1x |

- 외장 모니터가 **위쪽**에 있어서 y 가 **음수**다. 정상이다. 배치는 바뀔 수 있으니 `info` 로 확인한다.
- 레티나(2x) 캡처 이미지는 포인트의 2배 픽셀이고, `--max` 로 줄이면 또 달라진다.
  **이미지 픽셀을 그대로 클릭 좌표로 쓰면 틀린다.** `capture` 가 출력하는 환산식으로 바꾼다.
- `windows`·`ui`·`cursor` 가 주는 값은 이미 화면 좌표라 그대로 쓴다.

## 일하는 순서

1. `info` — 화면 배치·권한 확인.
2. `windows <앱>` — 대상 창의 창id·좌표.
3. `front <앱> [창제목]` — 앞으로. **키 입력은 앞 앱에만 들어간다.**
4. `ui <앱>` — 누를 버튼·입력칸의 중심 좌표. 맥 앱은 대부분 여기서 정확한 좌표가 나온다.
   요소가 안 나오는 앱(일부 Electron 앱 등)만 `capture --window <창id>` 로 보고 좌표를 정한다.
5. `click` / `type --to <앱>` / `key --to <앱>` 으로 조작. **`--to` 를 항상 붙인다** —
   앞 앱이 다르면 보내지 않고 오류로 끝난다.
6. `capture --window <창id>` 로 **결과를 확인한다.** 눌렀다고 눌린 게 아니다.

## 입력 — 한글 입력기 함정

- 키를 "문자"로 보내면 한글 입력기가 켜져 있을 때 `abc` 가 `무추` 로 들어간다. 그래서
  - `type` 은 클립보드 붙여넣기(⌘V)로 넣는다. 한글·영문 모두 안전. 원래 클립보드 내용은
    끝나고 되돌린다(이미지·서식 포함).
  - `key` 는 키코드로 보낸다. 입력기 상태와 무관하다.
- Karabiner 의 윈도우식 매핑은 물리 키보드에만 걸린다. 이 스크립트가 보내는 키는
  **맥 원래 단축키** 기준이다 — 복사 `cmd+c`, 저장 `cmd+s`, 창 닫기 `cmd+w`.

## ⚠️ 시험할 때 — 윈도우에서 실제로 사고 났던 교훈

- **사용자가 쓰고 있는 앱에 시험 입력하지 않는다.** 내가 만든 빈 파일을 열어서 한다:
  `open -a TextEdit <내가 만든 파일>` (텍스트 편집기는 파일마다 새 창을 띄운다).
- 창 제목 옆 "편집됨"·점 표시는 **미저장 변경분**이다. 건드리지 않는다.
- 되돌릴 때 `cmd+z` 는 **한 번 누르고 확인한다.** 연타하면 남의 작업을 지운다.
- 사용자가 맥을 쓰는 중이면 포커스와 커서를 뺏게 된다. 끝나면 **원래 앞 앱과 커서 위치로
  돌려놓고**(`front <원래 pid>`, `move <원래 좌표>`) 그렇게 했다고 말한다.

## 하지 말아야 할 것

- **비밀번호·카드번호·주민번호·API 키를 입력하지 않는다.** 로그인 창이 나오면 사용자에게 넘긴다.
- **캡차를 풀지 않는다.**
- **승인·권한 창을 대신 누르지 않는다.** Claude 앱의 도구 승인 창, macOS 의 권한·보안 대화상자
  (손쉬운 사용·화면 기록·키체인·관리자 암호), 시스템 설정의 보안 항목은 사람이 누르라고 있는 창이다.
- **다른 도구에서 거부된 동작을 이 스킬로 우회하지 않는다.** 막혔으면 사용자에게 알리고 사용자가 정하게 한다.
- **화면 전체 캡처에는 메신저·메일이 같이 찍힌다.** 필요한 창만 `--window` 로 찍고,
  캡처 이미지를 사용자 밖으로 보내지 않는다.
- 되돌리기 어려운 버튼(삭제·전송·결제·확인)은 **누르기 전에 물어본다.**
  메신저(카카오톡·팀즈·슬랙)에서는 `return` 이 곧 전송이다.

## 알려진 제약

- `windows`·`capture --window` 는 **화면에 보이는 창만** 다룬다. 최소화된 창은 `front` 로 먼저 복원한다.
- 전체화면 앱(별도 Space)은 `front` 뒤 화면 전환이 끝날 때까지 잠깐 기다렸다가 확인한다.
- `ui` 는 앱에 따라 느리다. 크롬·팀즈 같은 Electron 앱은 수 초 걸리거나 요소가 거의 안 나올 수 있다.
  깊이·최대줄을 줄여 쓰고, 안 나오면 캡처로 간다.
- 스크롤 양은 줄 단위라 앱마다 움직이는 거리가 다르다. 스크롤 후 캡처로 확인한다.
